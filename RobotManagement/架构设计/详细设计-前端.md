# 前端详细设计

> 版本：v2.0 | 日期：2026-05-14  
> 设计方向：参考讯飞开放平台的网站与控制台风格，构建“机器人运营控制台”式前端体验

---

## 一、设计定位

前端是机器人运营管理平台的统一操作界面。新版设计不再采用传统后台的纯表格菜单形态，而是借鉴讯飞开放平台的产品化表达方式：以“机器人服务、任务编排、告警运维、文档支持”为核心结构，让平台既能承载高频运维操作，也具备开放平台式的清晰入口和专业感。

### 1.1 风格参考

参考讯飞开放平台呈现出的以下特征：

| 特征 | 在本平台中的落地 |
|------|----------------|
| 开放平台式首页 | 登录后默认进入工作台，提供服务概览、快速接入、告警态势、常用操作 |
| 能力卡片矩阵 | 将机器人同步、实时巡检、任务下发、告警运维、权限管理做成能力入口 |
| 蓝白科技视觉 | 使用高饱和蓝作为主色，搭配浅蓝背景、白色内容区、少量青色高亮 |
| 控制台心智 | 围绕租户、已同步机器人、巡检状态、任务状态、告警状态组织页面 |
| 文档中心入口 | 在平台内提供机器人来源说明、Topic 说明、错误码和运维检查项 |
| 开发者友好 | 外部授权平台边界、MQTT Topic、状态码均给出可检查的说明 |

### 1.2 体验原则

- **首页即控制台**：用户登录后直接看到设备态势和待处理事项，不做营销落地页。
- **外部授权边界清晰**：机器人首次授权、APP ID、API 凭证由外部授权平台负责，当前平台只消费已授权机器人。
- **运维效率优先**：巡检、告警、任务下发等高频操作保持短路径，避免为了展示感牺牲效率。
- **信息分层清晰**：全局导航负责业务域，侧边导航负责域内页面，内容区负责当前任务。
- **实时状态突出**：在线、离线、告警、任务执行中等状态在导航、列表、地图和详情中保持一致。

## 二、技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 框架 | React 18 | 组件化开发，生态成熟 |

## 三、视觉规范

### 3.1 视觉关键词

整体风格定位为：**清爽、可信、科技、开放平台、控制台效率**。

页面以白色和浅蓝灰为底，主操作、选中态和关键数据使用蓝色表达；地图、实时状态、告警等高密度区域使用更强的层级和状态色。避免过度装饰，页面重心放在数据、状态和操作入口上。

## 四、整体信息架构

### 4.1 全局布局

采用“顶部全局导航 + 左侧模块导航 + 主内容区”的开放平台控制台布局。

```
┌────────────────────────────────────────────────────────────────────┐
│ Logo  机器人运营管理平台   工作台  机器人服务  任务编排  告警运维  文档支持 │
│                         全局搜索 / 通知 / 帮助 / 租户 / 用户菜单        │
├───────────────┬────────────────────────────────────────────────────┤
│ 模块侧边导航   │ 页面标题 / 操作区 / 筛选区                            │
│               ├────────────────────────────────────────────────────┤
│ 当前业务域菜单 │ 主内容区：能力卡片、数据表格、地图、表单、详情抽屉        │

```

顶部导航承载平台级业务域，侧边导航根据当前业务域切换。这样既保留开放平台的横向产品入口，也保留运维后台的纵向操作效率。

### 4.2 顶部导航

| 导航项 | 说明 |
|--------|------|
| 工作台 | 默认首页，展示机器人态势、告警、任务、同步状态 |
| 机器人服务 | 巡检面板、机器人列表、机器人详情、历史轨迹 |
| 任务编排 | 任务下发、任务列表、即时指令记录 |
| 告警运维 | 告警中心、告警规则、通知配置、运行日志入口 |
| 权限管理 | 运营人员、角色、机器人访问授权 |
| 文档支持 | 机器人来源说明、MQTT Topic、VDA5050 字段说明、错误码 |

## 六、登录与认证

### 6.1 登录页风格

登录页采用开放平台官网式蓝白科技视觉，但保持表单聚焦。

```
┌──────────────────────────────────────────────────────────────┐
│ 左侧品牌区：机器人运营管理平台 / VDA5050 / MQTT / 实时巡检     │
│ 浅蓝科技背景、能力标签、机器人来源摘要                         │
├──────────────────────────────┬───────────────────────────────┤
│                              │ 登录卡片                       │
│                              │ 用户名 / 密码 / 登录按钮        │
│                              │ 错误提示 / 首次改密入口          │
└──────────────────────────────┴───────────────────────────────┘
```

左侧仅作为品牌和信任背书，不放复杂营销内容；右侧登录表单保持简单。

### 6.2 认证流程

```
用户输入用户名 + 密码
    → POST /api/auth/login
    → 成功：Access Token 写入 Zustand 内存
    → Refresh Token 由后端 Set-Cookie 写入 httpOnly Cookie
    → 跳转 /workbench
    → 失败：显示统一错误
    → 423：显示账号锁定提示
    → password_reset_required：跳转修改密码页
```

### 6.3 Token 自动刷新

Axios 响应拦截器处理 401：

```
请求返回 401
    → 若未刷新：调用 POST /api/auth/refresh（不传 refreshToken Body，浏览器自动携带 Cookie）
    → 若正在刷新：请求进入等待队列
    → 刷新成功：重放原请求
    → 刷新失败：清空认证态并跳转 /login
```

并发 401 只触发一次刷新，避免重复请求。

Cookie 与跨域要求：

- Refresh Token Cookie 必须由后端设置为 `HttpOnly; Secure; SameSite=Strict/Lax; Path=/api/auth`。
- 前端 JavaScript 不读取、不保存、不拼接 Refresh Token。
- 若前后端跨域部署，Axios 需要开启 `withCredentials: true`，后端 CORS 只允许可信域名。
- `/api/auth/refresh`、`/api/auth/logout` 由后端校验 `Origin` / `Referer`，降低 CSRF 风险。

## 七、机器人来源与同步设计

机器人首次授权、APP ID、API Key / API Secret、EMQX 认证回调与凭证吊销，统一放到外部授权平台建设。当前平台不提供开放接入菜单，也不展示或管理机器人通信凭证。

### 7.1 平台边界

| 能力 | 当前平台 | 外部授权平台 |
|------|----------|--------------|
| 机器人首次授权 / 激活 | 不负责 | 负责 |
| APP ID 与接入配额 | 不展示、不管理 | 负责 |
| API Key / Secret | 不展示、不创建、不缓存 | 负责 |
| 已授权机器人同步 | 负责 | 提供数据源 |
| 巡检、任务、告警 | 负责 | 不负责 |
| 运营人员访问授权 | 负责 | 不负责 |

### 7.2 同步入口

路由：`/robots/list`

列表顶部提供“同步机器人”按钮，触发后端调用外部授权平台或读取外部授权数据源。若暂未打通接口，按钮进入加载态后给出“同步能力待联调”的业务提示，不暴露 APP ID / 凭证概念。

同步结果采用轻量反馈：

- 成功：提示新增、更新、失效的机器人数量。
- 部分失败：展示失败原因和可重试入口。
- 全部失败：展示外部平台不可用、鉴权失败或数据格式异常。

### 7.3 机器人来源说明

路由：`/docs/quickstart`

该页面不再是“接入指引”，而是“机器人来源与同步说明”，用于告诉运营人员：

1. 机器人授权和首次激活在外部授权平台完成。
2. 当前平台通过同步接口获取已授权机器人清单。
3. 机器人同步成功后出现在机器人列表中。
4. 运营人员在本平台继续进行巡检、任务下发、告警处理和访问授权。

页面可提供外部授权平台链接，链接地址使用运行时配置项，例如 `VITE_AUTH_PLATFORM_URL`。未配置时隐藏跳转按钮，只保留说明。

### 7.4 Topic 查看

Topic 说明保留在文档中心，但只用于运维排障和联调说明，不承担凭证调试功能。

功能：

- 选择已同步机器人后展示其 Topic：
  - `uagv/v3/{manufacturer}/{serialNumber}/state`
  - `uagv/v3/{manufacturer}/{serialNumber}/visualization`
  - `uagv/v3/{manufacturer}/{serialNumber}/connection`
  - `uagv/v3/{manufacturer}/{serialNumber}/order`
  - `uagv/v3/{manufacturer}/{serialNumber}/instantActions`
- 支持复制 Topic。
- 展示最近收到的 state/connection 消息摘要。
- 不提供 API Key、API Secret、APP ID 或 MQTT 账号密码输入框。

## 八、实时巡检设计

巡检面板是高频工作界面，设计上采用“地图为主、状态为辅、操作悬浮”的结构。

### 8.1 页面结构

```
┌────────────────────────────────────────────────────────────────────┐
│ 顶部工具条：机器人筛选 / 在线状态 / 告警级别 / 地图选择 / 全屏       │
├────────────────┬───────────────────────────────────────────────────┤
│ 机器人列表       │ 实时地图                                          │
│ SN / 在线 / 告警 │ 机器人位置、方向、轨迹、选中态、悬浮信息              │
├────────────────┴───────────────────────────────────────────────────┤
│ 底部状态栏：电量 / 速度 / 当前任务 / 运行模式 / 连接状态 / 即时指令   │
└────────────────────────────────────────────────────────────────────┘
```

### 8.2 机器人列表

- 支持按 SN、厂商、状态、告警级别搜索筛选。
- 在线状态使用圆点 + 文案：在线、离线、异常断连、休眠。
- 告警状态使用右侧窄色条表示，避免列表过于拥挤。
- 点击机器人后地图居中并打开悬浮状态面板。

### 8.3 实时地图

地图区域使用浅色工业平面图风格，重点突出机器人和路径。

实时位置更新：

```
WebSocket 收到 position
    → 更新 Konva 节点 x/y/rotation
    → 追加轨迹点，保留最近 5 分钟
    → requestAnimationFrame 合并渲染
```

性能策略：

- 高频位置不进入 Zustand。
- 地图对象和轨迹线直接操作 Konva Layer。
- visualization 最高 10Hz，前端可按设备数量进行降采样。
- 多机器人同时显示时，未选中机器人降低标签密度。

### 8.4 状态面板

选中机器人后右侧或底部展示状态面板：

| 字段 | 来源 |
|------|------|
| 电量 | `batteryState.batteryCharge` |
| 充电状态 | `batteryState.charging` |
| 速度 | `velocity.vx / vy / omega` |
| 运行模式 | `operatingMode` |
| 当前任务 | `orderId` |
| 急停状态 | `safetyState.eStop` |
| 错误列表 | `errors` |

安全急停状态、FATAL、CONNECTION_BROKEN 使用红色横幅提示，并提供“查看告警详情”入口。安全急停来自机器人 `safetyState.eStop` 上报，是状态展示和告警，不作为平台通用远程下发指令。

### 8.5 即时指令

viewer 不展示写操作。operator/admin 可见：

| 按钮 | actionType | 交互 |
|------|------------|------|
| 暂停 / 停止移动 | `stopPause` | 红色高风险按钮，二次确认 |
| 继续 | `startPause` | 主按钮 |
| 取消任务 | `cancelOrder` | 二次确认 |

按钮使用图标 + tooltip，危险操作必须明确显示影响范围。若后续需要远程安全急停，必须单独确认厂商支持的 actionType 或硬件安全链路，不复用 `stopPause`。

## 十四、WebSocket 连接管理

### 14.1 连接建立

```
用户登录成功
    → 建立 STOMP WebSocket 连接
    → CONNECT Header 携带 Authorization: Bearer <token>
    → 订阅全局告警 Topic
    → 进入具体页面后订阅机器人级 Topic
```

### 14.2 订阅管理

| Topic | 页面 | 更新目标 |
|-------|------|----------|
| `/topic/alerts` | 全局 | 告警红点、全局通知、告警中心 |
| `/topic/robots/{id}/state` | 巡检 / 详情 | 状态卡片 |
| `/topic/robots/{id}/position` | 巡检 / 历史轨迹 | 地图位置 |
| `/topic/robots/{id}/connection` | 列表 / 巡检 | 在线状态 |
| `/topic/robots/{id}/order-status` | 任务列表 | 任务状态 |

切换机器人时取消旧订阅，建立新订阅，避免消息堆积。

订阅鉴权要求：

- 后端必须在 STOMP `CONNECT` 阶段校验 JWT 签名、有效期和黑名单。
- 后端必须在每次 `SUBSCRIBE` 阶段校验订阅目标资源归属：`tenant_id` 一致，且 operator/viewer 对目标机器人有访问权。
- `admin` 可订阅本租户全部机器人 Topic；`operator` 和 `viewer` 只能订阅已授权机器人 Topic。
- 前端隐藏菜单和按钮只用于体验优化，不能作为订阅鉴权依据。

### 14.3 断线重连

- 重连间隔指数退避：1s → 2s → 4s → 最大 30s。
- 重连成功后恢复订阅。
- 调用 REST 接口补拉最新状态，避免断线期间漏消息。
- 页面顶部显示轻量连接状态：已连接、重连中、连接失败。

## 十六、错误处理与空状态

### 16.1 HTTP 错误处理

| 状态码 | 处理 |
|--------|------|
| 401 | 自动刷新 Token，失败后跳转登录 |
| 403 | 提示无权限，并隐藏后续危险操作 |
| 409 | 业务冲突，由页面给出明确原因，如机器人离线 |
| 423 | 提示账号已锁定 |
| 429 | 提示操作过于频繁，展示 Retry-After |
| 500 | 提示服务器错误 |
| 503 | 提示服务暂不可用，建议稍后重试 |

### 16.2 空状态

空状态采用开放平台式引导，不只显示“暂无数据”。

| 场景 | 空状态文案 | 操作 |
|------|------------|------|
| 无机器人 | 当前租户还没有接入机器人 | 查看接入指引 / 创建 APP ID |
| 无 APP ID | 还没有可用于机器人接入的 APP ID | 创建 APP ID |
| 无任务 | 当前机器人暂无任务记录 | 新建任务 |
| 无告警 | 暂无未解决告警 | 查看告警规则 |
| 无凭证 | 当前机器人暂无 API 凭证 | 创建凭证 |
