# 机器人授权平台 — 后端设计

> 版本：v1.0 | 日期：2026-05-15  
> 定位：独立的机器人授权后端，负责机器人首次接入、APP ID 配额、API 凭证、EMQX 认证回调与授权数据同步。

---

## 一、设计边界

机器人授权后端只负责机器人通信身份与 MQTT 接入权限，不负责运营管理中的巡检、任务、告警和运营人员机器人访问范围。

| 能力 | 授权平台后端 | 运营管理平台后端 |
|------|--------------|------------------|
| APP ID / 配额 | 负责 | 不负责 |
| 机器人首次注册 / 激活 | 负责 | 不负责 |
| API Key / API Secret | 负责 | 不存储、不展示 |
| EMQX HTTP 认证回调 | 负责 | 不负责 |
| MQTT ACL 动态下发 | 负责 | 不负责 |
| 已授权机器人同步 API / 事件 | 负责提供 | 负责消费 |
| 巡检、任务、告警 | 不负责 | 负责 |

## 二、核心流程

### 2.1 首次授权激活

```
机器人使用 APP ID + SN 连接 EMQX
    → EMQX 调用授权平台 /internal/mqtt/auth
    → 校验 APP ID 是否存在、状态是否 active
    → 校验配额是否可用
    → 创建或复用 robots 记录，状态为 pending
    → 返回受限 ACL：允许发布 connection，允许订阅 activation
    → 机器人发布 connection ONLINE
    → 后端生成 API Key / API Secret
    → 通过 activation Topic 下发凭证
    → 机器人持久化凭证并使用 API Key / Secret 重连
    → /internal/mqtt/auth 校验凭证通过
    → robots.status 更新为 active，写激活审计
```

### 2.2 已授权机器人重连

```
机器人使用 API Key / API Secret 连接 EMQX
    → EMQX 调用 /internal/mqtt/auth
    → 查 api_credentials
    → 校验 Secret hash、凭证状态、机器人状态
    → 返回完整 ACL
```

### 2.3 凭证重发

适用于机器人本地凭证丢失或凭证轮换。

```
admin 发起凭证重发
    → 吊销旧凭证
    → 创建新 API Key / API Secret
    → 写 Redis robot:credential-reissue:{robotId}
    → 机器人重新使用 APP ID + SN 接入时，下发新凭证
```

## 三、数据模型

### 3.1 tenant_app_ids

```sql
CREATE TABLE tenant_app_ids (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id    UUID NOT NULL,
    app_id       TEXT NOT NULL UNIQUE,
    name         TEXT NOT NULL,
    robot_quota  INT NOT NULL DEFAULT 0,
    status       TEXT NOT NULL DEFAULT 'active'
                 CHECK (status IN ('active','revoked')),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 3.2 robots

```sql
CREATE TABLE robots (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id          UUID NOT NULL,
    tenant_app_id      UUID NOT NULL REFERENCES tenant_app_ids(id),
    serial_number      TEXT NOT NULL,
    manufacturer       TEXT,
    status             TEXT NOT NULL DEFAULT 'pending'
                       CHECK (status IN ('pending','active','revoked','disabled')),
    first_seen_at      TIMESTAMPTZ,
    last_seen_at       TIMESTAMPTZ,
    activated_at       TIMESTAMPTZ,
    revoked_at         TIMESTAMPTZ,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (tenant_id, serial_number)
);
```

### 3.3 api_credentials

```sql
CREATE TABLE api_credentials (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    robot_id        UUID NOT NULL REFERENCES robots(id),
    api_key         TEXT NOT NULL UNIQUE,
    api_secret_hash TEXT NOT NULL,
    permissions     JSONB NOT NULL,
    status          TEXT NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active','revoked','expired')),
    description     TEXT,
    expires_at      TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    revoked_at      TIMESTAMPTZ
);
```

### 3.4 activation_records

```sql
CREATE TABLE activation_records (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    robot_id       UUID REFERENCES robots(id),
    tenant_app_id  UUID REFERENCES tenant_app_ids(id),
    serial_number  TEXT NOT NULL,
    manufacturer   TEXT,
    stage          TEXT NOT NULL,
    success        BOOLEAN NOT NULL,
    reason         TEXT,
    detail         JSONB,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 3.5 audit_logs

```sql
CREATE TABLE audit_logs (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id   UUID NOT NULL,
    operator_id UUID,
    action      TEXT NOT NULL,
    resource    TEXT NOT NULL,
    resource_id TEXT NOT NULL,
    detail      JSONB,
    ip          INET,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 四、接口设计

### 4.1 APP ID

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/app-ids` | 查询 APP ID 列表 | admin / operator / viewer |
| POST | `/api/app-ids` | 创建 APP ID | admin |
| PUT | `/api/app-ids/{id}` | 修改名称、配额 | admin |
| POST | `/api/app-ids/{id}/revoke` | 吊销 APP ID | admin |

### 4.2 授权机器人

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/robots` | 查询授权机器人列表 | admin / operator / viewer |
| GET | `/api/robots/{id}` | 查询授权机器人详情 | admin / operator / viewer |
| POST | `/api/robots/{id}/revoke` | 吊销机器人 | admin |
| POST | `/api/robots/{id}/disable` | 禁用机器人 | admin |
| POST | `/api/robots/{id}/credentials/reissue` | 重发凭证 | admin |

### 4.3 API 凭证

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/robots/{id}/credentials` | 查询凭证列表，不返回 Secret | admin |
| POST | `/api/robots/{id}/credentials` | 创建新凭证，Secret 仅返回一次 | admin |
| POST | `/api/robots/{id}/credentials/{credentialId}/revoke` | 吊销凭证 | admin |

### 4.4 激活记录

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/activation-records` | 查询激活记录 | admin / operator / viewer |
| GET | `/api/activation-records/{id}` | 查询激活详情 | admin / operator / viewer |

### 4.5 运营平台同步

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/openapi/authorized-robots` | 给运营平台拉取已授权机器人清单 | service token |
| GET | `/openapi/authorized-robots/{id}` | 给运营平台查询单台机器人 | service token |
| POST | `/openapi/authorized-robots/events/replay` | 重放授权变更事件 | admin / service token |

同步接口不返回 API Secret，不返回 api_secret_hash。

## 五、EMQX 认证回调

### 5.1 回调接口

`POST /internal/mqtt/auth`

该接口只允许 EMQX 内网访问，不对公网开放。

请求示例：

```json
{
  "username": "app_id_or_api_key",
  "password": "sn_or_api_secret",
  "clientid": "robot-sn",
  "peerhost": "10.0.0.8"
}
```

### 5.2 认证分支

| 分支 | Username | Password | 处理 |
|------|----------|----------|------|
| 首次接入 | APP ID | SN | 校验 APP ID、配额、SN，返回受限 ACL |
| 已授权接入 | API Key | API Secret | 校验凭证 hash，返回完整 ACL |

### 5.3 ACL 范围

首次接入仅允许：

```text
publish:   uagv/v3/{manufacturer}/{serialNumber}/connection
subscribe: uagv/v3/{manufacturer}/{serialNumber}/activation
```

已授权接入允许：

```text
publish:   uagv/v3/{manufacturer}/{serialNumber}/state
publish:   uagv/v3/{manufacturer}/{serialNumber}/visualization
publish:   uagv/v3/{manufacturer}/{serialNumber}/connection
publish:   uagv/v3/{manufacturer}/{serialNumber}/factsheet
subscribe: uagv/v3/{manufacturer}/{serialNumber}/order
subscribe: uagv/v3/{manufacturer}/{serialNumber}/instantActions
```

## 六、安全要求

- API Secret 只在创建或重发时返回一次。
- 数据库存储 `api_secret_hash`，不存明文 Secret。
- Secret hash 使用 BCrypt 或 Argon2。
- EMQX 回调接口只允许内网访问，并增加固定服务鉴权 Header。
- 所有吊销、重发、配额修改都写审计日志。
- APP ID 泄露时可吊销 APP ID，但已激活机器人的 API 凭证是否联动吊销由策略配置决定。
- 授权平台对运营平台同步接口使用 service token 或 mTLS。

## 七、Redis Key

| Key | 内容 | TTL |
|-----|------|-----|
| `auth:refresh:{token_hash}` | 前端登录 Refresh Token | 7 天 |
| `mqtt:auth:fail:{clientid}` | MQTT 认证失败计数 | 15 分钟 |
| `robot:credential-reissue:{robotId}` | 凭证重发标记 | 10 分钟 |
| `robot:activation-lock:{serialNumber}` | 激活并发锁 | 30 秒 |

## 八、与运营管理平台的数据关系

授权平台是机器人身份源。运营管理平台只保存同步后的业务副本，例如：

```text
external_robot_id
tenant_id
serial_number
manufacturer
status
synced_at
```

运营管理平台不得保存：

- API Secret
- api_secret_hash
- 可用于 MQTT 认证的 Password
- 授权平台内部管理 Token

授权变更后建议发布事件：

```json
{
  "eventType": "ROBOT_AUTHORIZED",
  "robotId": "external-id",
  "tenantId": "tenant-id",
  "serialNumber": "SN-001",
  "manufacturer": "JSYS",
  "status": "active",
  "occurredAt": "2026-05-15T10:00:00Z"
}
```

事件类型：

- `ROBOT_AUTHORIZED`
- `ROBOT_REVOKED`
- `ROBOT_DISABLED`
- `ROBOT_UPDATED`

## 九、MVP 范围

纳入 MVP：

- APP ID 创建、修改配额、吊销
- EMQX HTTP 认证回调
- 机器人首次激活
- API Key / API Secret 生成、吊销、重发
- 激活记录
- 审计日志
- 已授权机器人同步接口

暂缓：

- 凭证自动轮换
- 多级审批
- 多租户独立密钥体系
- 复杂风控策略
- 批量导入和批量授权
