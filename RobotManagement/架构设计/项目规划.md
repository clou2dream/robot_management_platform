## 三、里程碑规划

> 以 5 个工作日为一个里程碑，单人顺序开发，后端接口优先，前端跟进联调。
>
> **交付策略**：M1–M2 完成后（Day 12）即可交付 MVP 可用版本，覆盖授权、巡检、任务下发核心功能；M3–M5 继续迭代完整功能。

### M1（Day 1–5）：环境就绪 + 认证可用　`MVP`

**目标：** 服务器跑起来，能登录系统。

| 任务 |
|------|
| 购买 ECS、配置安全组、域名解析、SSL |
| Docker Compose 部署 PostgreSQL+TimescaleDB、Redis、EMQX、Nginx |
| 初始化数据库 Schema（全部建表、索引） |
| Spring Boot 项目骨架（MyBatis-Plus、Security、Swagger） |
| 登录 / 刷新 / 注销接口 + JWT Filter + 失败锁定 |
| Vite + React 项目骨架（路由、Axios 封装、Zustand） |
| 前端登录页 + Token 自动刷新拦截器 + 路由权限守卫 |

**验收标准：** 浏览器能打开登录页，输入账号密码后跳转到首页（空页面），刷新后保持登录状态。

---

### M2（Day 6–12）：机器人授权 + 巡检 + 任务下发 + 告警　`MVP 交付`

**目标：** 核心功能全部可用，可上线使用。

| 任务 |
|------|
| EMQX HTTP 认证回调接口（两阶段认证 + ACL） |
| 机器人首次上线自动注册 + 凭证下发逻辑 |
| 机器人 CRUD 接口（列表、吊销、重新激活） |
| MQTT 订阅服务 + state / visualization / connection 处理器 |
| Redis 快照更新 + TimescaleDB 异步写入 |
| Spring WebSocket + STOMP 服务端（租户隔离推送） |
| 告警引擎（触发、去重、自动恢复、写库）+ 告警接口 |
| Order 下发接口 + instantActions 接口 + 任务状态跟踪 |
| 前端机器人列表页（含在线状态实时更新） |
| 前端巡检面板（机器人列表 + 状态卡片 + 即时指令操作区） |
| 前端实时地图（Konva.js，机器人位置 + 轨迹） |
| 前端任务下发页（地图选点、节点配置、下发、任务列表） |
| 导航栏告警红点（CRITICAL/FATAL 弹出全局通知） |
| 生产部署 + 上线检查 |

**验收标准：** 机器人上线自动激活；巡检面板实时展示位置和状态；能下发任务并跟踪状态；异常触发告警前端可见。**MVP 在此里程碑结束后交付。**

## 四、风险提示

| 风险 | 影响 | 应对 |
|------|------|------|
| Konva.js 实时地图开发复杂度超预期 | M3 延期 1–2 天 | 优先实现基础位置显示，轨迹回放放到 M5 |
| EMQX HTTP 认证回调调试耗时 | M2 延期 1 天 | 提前用 MQTT 工具验证认证流程 |
| VDA5050 报文与实际机器人不完全兼容 | M4 延期 | 尽早拿到真实机器人或厂商 SDK 联调 |
| 前后端接口联调返工 | 各里程碑均有影响 | 后端优先完成 Swagger 文档，前端用 Mock 并行开发 |
