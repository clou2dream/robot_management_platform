# 机器人运营管理平台 — 技术架构设计

> 版本：v1.0 | 日期：2026-05-12

---

## 一、项目概述

机器人运营管理平台，面向多租户场景，支持机器人授权激活、实时巡检监控、任务指令下发及运营人员权限管理。系统遵循 VDA5050 v3.0 标准，通过 MQTT 协议与机器人通信。

**核心约束**
- 流量规模：最高几十 QPS，无高并发压力
- 实时性要求：巡检数据实时展示，机器人状态变更秒级感知
- 可靠性要求：授权一次永久有效，机器人离线后仍可正常工作
- 扩展性要求：多租户架构，支持未来横向扩展

### 2.2 安全设计

安全功能全部内置于 Spring Boot，无独立网关进程。

**职责划分**

| 层次 | 组件 | 职责 |
|------|------|------|
| 接入层 | Nginx | SSL 终止、静态资源服务、WebSocket 代理 |
| 认证鉴权 | Spring Security | JWT 验证、租户隔离、操作权限校验 |
| 限流 | Bucket4j + Redis | 接口级限流，按 tenant_id 隔离 |
| 审计 | Spring AOP | 操作日志记录 |

**认证流程**

```
请求到达 Spring Boot
    → Spring Security Filter 提取 JWT
    → 验证签名和有效期（查 Redis 黑名单确认未注销）
    → 解析 tenant_id、operator_id 存入 SecurityContext
    → Bucket4j 限流检查（按 tenant_id 隔离）
    → 进入业务逻辑，从 SecurityContext 取身份信息
```

**限流规则（示例）**

| 接口 | 限流策略 |
|------|----------|
| 任务下发 `/orders` | 每个 tenant 10次/秒 |
| 即时指令 `/instant-actions` | 每个 tenant 20次/秒 |
| 普通查询接口 | 每个 tenant 100次/秒 |

**MQTT 通道独立认证**，EMQX 通过 HTTP 回调后端 `/internal/mqtt/auth` 做机器人认证，该接口仅内网可访问，不对外暴露。

| 层次 | 技术选型 | 选型理由 |
|------|----------|----------|
| 接入层 | Nginx | SSL 终止、静态资源、WebSocket 代理 |

## 三、功能模块设计

### 3.1 模块一：机器人授权

**核心原则：一次授权，永久有效，支持离线使用**

**配额激活模式**

采用配额激活模式，机器人无需平台预录入。租户可创建多个 APP ID，每个 APP ID 独立配额。硬件团队出厂时将对应 APP ID + SN 烧录到机器人本地，机器人首次上线自动完成注册和凭证下发。

**授权流程**

```
机器人上电，用租户 APP ID + SN 连接 EMQX
    → EMQX 回调后端 /internal/mqtt/auth 验证
    → 后端查 tenant_app_ids 表确认 APP ID 有效
    → 检查配额：该 APP ID 下已注册数量（status IN pending/active）< robot_quota，否则拒绝
    → 在 robots 表创建记录（status='pending'），返回允许连接（受限 ACL）
    → 机器人上线后发布 connection 消息，后端获取 manufacturer，生成 API Key 和 API Secret，发布到 activation Topic
    → 机器人收到后持久化存储 API Key、API Secret
    → 后续断网重连均使用 API Key + API Secret 连接 EMQX，获得完整 Topic 权限
    → 即使断网，本地凭证仍有效
```

> 已激活机器人若丢失本地凭证，可退回用 APP ID + SN 重新接入，后端检测后自动吊销旧凭证并重新下发新凭证，详见模块一详细设计 4.2。

**配额管理**

- 已注册数量达到配额 80% 时触发 WARNING 告警，通知租户 admin
- admin 可清理 status=pending 且从未上报过 state 的幽灵机器人释放配额
- 发现 APP ID 泄露时可轮换租户 APP ID，已激活机器人不受影响

**robots 表状态机**

```
pending（已注册，未完成首次 api_key 认证）→ active（已激活）→ revoked（已吊销）→ active（重新激活）
```

- `app_id` 字段（机器人业务身份）在激活时生成并永久保留
- 吊销操作在机器人下次联网时生效（EMQX 认证回调返回拒绝）
- 租户 APP ID 存储在 tenant_app_ids 表，机器人级 app_id 存储在 robots 表，两者不同

**授权 Topic**
```
uagv/v3/{manufacturer}/{serialNumber}/activation   # 平台 → 机器人，下发 API Key + API Secret
```

**MQTT 认证方式**

机器人授权后连接 EMQX 时携带：
- **Username**：`api_key`
- **Password**：`api_secret`

> `app_id` 是机器人的业务身份标识，不用于 MQTT 认证。

EMQX 通过 HTTP 认证插件回调后端 `/internal/mqtt/auth`，后端查库确认凭证有效性后返回允许/拒绝。该接口仅内网可访问，不对外暴露。

### 3.2 模块二：机器人巡检

**通信协议：VDA5050 v3.0 over MQTT**

**MQTT Topic 规范**

```
uagv/v3/{manufacturer}/{serialNumber}/state          # 完整状态上报（1-2Hz）
uagv/v3/{manufacturer}/{serialNumber}/visualization  # 高频位置流（最高10Hz）
uagv/v3/{manufacturer}/{serialNumber}/connection     # 连接状态（Last Will）
uagv/v3/{manufacturer}/{serialNumber}/factsheet      # 机器人能力描述（静态）
```

**数据流**

```
机器人 MQTT 上报
    → EMQX Broker 接收
    → 后端 MQTT 订阅服务消费
    → 解析 VDA5050 消息
    → 写入 TimescaleDB（持久化）
    → 更新 Redis 缓存（实时状态）
    → 通过 WebSocket 推送前端
    → 触发告警引擎检查
```

**告警规则（示例）**

| 触发条件 | 告警级别 | 通知方式 |
|----------|----------|----------|
| 电量 < 10% | URGENT | 平台弹窗 + 飞书 |
| 安全急停触发 | CRITICAL | 平台弹窗 + 飞书 |
| 连接异常中断（CONNECTION_BROKEN） | CRITICAL | 平台弹窗 + 飞书 |
| VDA5050 FATAL 错误 | FATAL | 平台弹窗 + 飞书 |

### 3.3 模块三：任务下发

**通信协议：VDA5050 v3.0 over MQTT**

**下发 Topic**

```
uagv/v3/{manufacturer}/{serialNumber}/order          # 导航任务
uagv/v3/{manufacturer}/{serialNumber}/instantActions # 即时指令（暂停/继续/取消任务等）
```

> 安全急停由机器人通过 `safetyState.eStop` 上报并触发告警，不复用 `stopPause` 作为通用远程急停指令；如需远程安全急停，需单独确认厂商扩展 actionType 或硬件安全链路。

**下发流程**

```
运营人员操作前端
    → 后端 API 接收请求
    → 权限校验（角色校验 + operator_robot_access 校验，详见模块四）
    → 构造 VDA5050 Order 报文
    → 发布到 EMQX
    → 记录任务到 orders 表
    → 订阅机器人 state 中的 actionStates 跟踪执行进度
```

### 3.4 模块四：权限控制

**权限层级**

```
Tenant（租户）
  └── Operator（运营人员）
        └── 可管理的 Robot 列表（operator_robot_access）
              └── Robot（app_id，机器人业务标识，激活时由平台生成，存储在 robots 表）
                    └── API Credential（api_key + api_secret + permissions）
```

**权限集合设计（RBAC + 资源级）**

```json
["state:read", "order:write", "instantAction:write", "config:write", "credential:manage"]
```

| 权限标识 | 说明 |
|----------|------|
| `state:read` | 查看机器人状态和巡检数据 |
| `order:write` | 下发导航任务 |
| `instantAction:write` | 下发即时指令（暂停、继续、取消任务等） |
| `config:write` | 修改机器人配置 |
| `credential:manage` | 管理 API Key/Secret |

**运营人员角色**

| 角色 | 说明 |
|------|------|
| `admin` | 租户管理员，可管理所有机器人和人员 |
| `operator` | 普通运营员，只能操作被授权的机器人 |
| `viewer` | 只读，只能查看状态 |

**登录方式**

平台采用自建账号体系，唯一登录方式为用户名 + 密码。飞书仅用于告警通知推送，不作为登录入口。

## 四、数据库设计

### 4.1 多租户策略

采用**共享数据库 + tenant_id 字段隔离**。直接持有业务数据的表（robots、operators、alerts、alert_notification_rules 等）携带 tenant_id，查询层强制过滤。通过外键关联间接归属租户的表（orders、api_credentials、operator_robot_access 等）不冗余存储 tenant_id，由 Service 层先校验父资源归属再查子资源。

### 4.2 表结构

#### 租户与权限体系

```sql
-- 租户
CREATE TABLE tenants (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name       TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 租户 APP ID（一个租户可有多个，每个独立配额）
CREATE TABLE tenant_app_ids (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id    UUID NOT NULL REFERENCES tenants(id),
    app_id       TEXT NOT NULL UNIQUE,  -- 机器人首次接入时用于租户身份验证
    name         TEXT,                  -- 便于区分，如"上海工厂"、"北京工厂"
    robot_quota  INT NOT NULL DEFAULT 0, -- 该 APP ID 下允许接入的机器人数量上限
    status       TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','revoked')),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 运营人员
CREATE TABLE operators (
    id                       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id                UUID NOT NULL REFERENCES tenants(id),
    username                 TEXT NOT NULL,
    password_hash            TEXT NOT NULL,
    role                     TEXT NOT NULL CHECK (role IN ('admin','operator','viewer')),
    password_reset_required  BOOLEAN NOT NULL DEFAULT FALSE,
    created_at               TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (tenant_id, username)
);

-- 机器人
CREATE TABLE robots (
    id                   UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id            UUID NOT NULL REFERENCES tenants(id),
    tenant_app_id        UUID NOT NULL REFERENCES tenant_app_ids(id), -- 注册时使用的 APP ID
    app_id               TEXT UNIQUE,                 -- 机器人业务身份标识，激活时生成
    serial_number        TEXT NOT NULL,
    manufacturer         TEXT,                        -- 来自机器人首次上线时发布的 connection 消息；注册时暂为 NULL，connection 消息到达后写入
    status               TEXT NOT NULL DEFAULT 'pending'
                         CHECK (status IN ('pending','active','revoked')),
    activated_at         TIMESTAMPTZ,
    created_at           TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (tenant_id, serial_number)
);

-- API 凭证（Key/Secret 对）
CREATE TABLE api_credentials (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    robot_id        UUID NOT NULL REFERENCES robots(id),
    api_key         TEXT NOT NULL UNIQUE,
    api_secret_hash TEXT NOT NULL,               -- bcrypt hash，不存明文
    permissions     JSONB NOT NULL,              -- 权限集合数组
    description     TEXT,
    expires_at      TIMESTAMPTZ,                 -- NULL 表示永不过期
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 运营人员 <-> 机器人 授权关系
CREATE TABLE operator_robot_access (
    operator_id UUID NOT NULL REFERENCES operators(id),
    robot_id    UUID NOT NULL REFERENCES robots(id),
    granted_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (operator_id, robot_id)
);

-- 告警通知规则（飞书 webhook，按机器人或租户级别配置）
-- scope: 'robot' 表示针对单台机器人，'tenant' 表示租户全局
CREATE TABLE alert_notification_rules (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id      UUID NOT NULL REFERENCES tenants(id),
    scope          TEXT NOT NULL CHECK (scope IN ('robot', 'tenant')),
    robot_id       UUID REFERENCES robots(id),   -- scope='robot' 时必填
    min_level      TEXT NOT NULL CHECK (min_level IN ('WARNING','URGENT','CRITICAL','FATAL')),
    feishu_webhook TEXT NOT NULL,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK (scope = 'tenant' OR robot_id IS NOT NULL)
);
```

#### 巡检时序数据

> **TimescaleDB 函数说明**
>
> - `create_hypertable(table, column)`：将普通 PostgreSQL 表转换为 TimescaleDB 超表（hypertable），按时间列自动分块存储。查询某个时间范围时只扫描相关分块，不做全表扫描，写入性能也显著优于普通表。
> - `add_retention_policy(table, interval)`：为超表注册自动数据清理策略，超过指定时长的历史分块会被定期删除，无需手写定时任务。

```sql
-- 启用 TimescaleDB
CREATE EXTENSION IF NOT EXISTS timescaledb;

-- 机器人完整状态（1-2Hz，长期保留）
CREATE TABLE robot_states (
    time           TIMESTAMPTZ NOT NULL,
    robot_id       UUID NOT NULL,
    -- 位置
    pos_x          DOUBLE PRECISION,
    pos_y          DOUBLE PRECISION,
    pos_theta      DOUBLE PRECISION,
    map_id         TEXT,
    localized      BOOLEAN,
    -- 速度
    vel_vx         DOUBLE PRECISION,
    vel_vy         DOUBLE PRECISION,
    vel_omega      DOUBLE PRECISION,
    -- 电池
    battery_soc    SMALLINT,
    battery_voltage DOUBLE PRECISION,
    charging       BOOLEAN,
    -- 运行状态
    operating_mode TEXT,
    driving        BOOLEAN,
    paused         BOOLEAN,
    order_id       TEXT,
    -- 完整原始报文（含 errors/loads/actionStates 等数组字段）
    raw_payload    JSONB,
    header_id      BIGINT
);
-- 转为超表，按 time 列自动分块；保留 90 天，超期分块自动清理
SELECT create_hypertable('robot_states', 'time');
SELECT add_retention_policy('robot_states', INTERVAL '90 days');

-- 高频位置流（最高10Hz，仅保留24小时，用于实时地图渲染）
CREATE TABLE robot_positions (
    time      TIMESTAMPTZ NOT NULL,
    robot_id  UUID NOT NULL,
    pos_x     DOUBLE PRECISION,
    pos_y     DOUBLE PRECISION,
    pos_theta DOUBLE PRECISION,
    map_id    TEXT,
    vel_vx    DOUBLE PRECISION,
    vel_vy    DOUBLE PRECISION
);
-- 转为超表；数据量最大，仅保留 24 小时，实时渲染用完即清
SELECT create_hypertable('robot_positions', 'time');
SELECT add_retention_policy('robot_positions', INTERVAL '24 hours');

-- 连接状态变更记录
CREATE TABLE robot_connections (
    time             TIMESTAMPTZ NOT NULL,
    robot_id         UUID NOT NULL,
    connection_state TEXT NOT NULL  -- ONLINE | OFFLINE | HIBERNATING | CONNECTION_BROKEN
);
-- 转为超表；保留 90 天，用于离线频率统计和故障回溯
SELECT create_hypertable('robot_connections', 'time');
SELECT add_retention_policy('robot_connections', INTERVAL '90 days');
```

#### 告警与任务

```sql

CREATE TABLE alerts (
```

### 4.3 索引设计

```sql
-- robot_states：按机器人查历史轨迹（最高频查询）
CREATE INDEX idx_robot_states_robot_time ON robot_states (robot_id, time DESC);

-- robot_positions：按机器人查最新位置
CREATE INDEX idx_robot_positions_robot_time ON robot_positions (robot_id, time DESC);

-- robot_connections：按机器人查连接历史
CREATE INDEX idx_robot_connections_robot_time ON robot_connections (robot_id, time DESC);

-- alerts：按机器人查未解决告警
CREATE INDEX idx_alerts_robot_unresolved ON alerts (robot_id, triggered_at DESC)
    WHERE resolved_at IS NULL;

-- orders：按机器人查进行中任务
CREATE INDEX idx_orders_robot_status ON orders (robot_id, status, created_at DESC);

-- audit_logs：按租户查操作记录
CREATE INDEX idx_audit_logs_tenant_time ON audit_logs (tenant_id, created_at DESC);

-- robots：按 app_id 查（业务查询路径，如按 APP ID 定位机器人）
CREATE INDEX idx_robots_app_id ON robots (app_id) WHERE app_id IS NOT NULL;

-- tenant_app_ids：按 app_id 查（机器人首次接入认证高频路径）
CREATE INDEX idx_tenant_app_ids_app_id ON tenant_app_ids (app_id);

-- api_credentials：按 api_key 查（MQTT 认证高频路径）
CREATE INDEX idx_api_credentials_api_key ON api_credentials (api_key);
```

### 4.4 Redis 缓存设计

| Key 模式 | 内容 | TTL |
|----------|------|-----|
| `robot:{id}:online` | 在线状态标志 | 10s（state/visualization 消息刷新） |
| `robot:{id}:state` | 最新 state 快照（JSON） | 无过期（覆盖更新） |
| `robot:{id}:position` | 最新位置（x,y,theta） | 无过期（覆盖更新） |
| `robot:reissue:{id}` | 凭证重新下发标记（已激活机器人退回 APP ID+SN 接入时写入） | 60s |

## 五、MQTT 接入设计

### 5.1 EMQX 认证配置

机器人认证分两个阶段，详见 3.1 模块一授权设计：

- **未授权阶段**：APP ID + SN，受限 ACL 仅允许发布 connection Topic 和订阅 activation Topic
- **已授权阶段**：API Key + API Secret 连接 EMQX，获得完整 Topic 读写权限

EMQX 通过 HTTP 认证插件回调后端 `/internal/mqtt/auth` 动态验证，该接口仅内网可访问。

### 5.2 Topic 权限控制

EMQX ACL 规则由后端动态下发，严格区分机器人的发布和订阅权限：

```
# 机器人允许发布（上报数据）
允许发布：uagv/v3/{manufacturer}/{serialNumber}/state
允许发布：uagv/v3/{manufacturer}/{serialNumber}/visualization
允许发布：uagv/v3/{manufacturer}/{serialNumber}/connection
允许发布：uagv/v3/{manufacturer}/{serialNumber}/factsheet

# 机器人允许订阅（接收指令）
允许订阅：uagv/v3/{manufacturer}/{serialNumber}/order
允许订阅：uagv/v3/{manufacturer}/{serialNumber}/instantActions
允许订阅：uagv/v3/{manufacturer}/{serialNumber}/activation

# 其他 Topic 一律拒绝，防止机器人越权发布指令或订阅其他机器人数据
```

## 六、实时推送设计

```
后端 MQTT 订阅服务
    → 解析消息
    → 写库（异步）
    → 推送 WebSocket Hub
        → 按 tenant_id + robot_id 路由
        → 推送到订阅该机器人的前端连接
```

前端通过 WebSocket 订阅感兴趣的机器人，后端维护订阅关系 Map，消息到达时精准推送，不广播。后端必须在 STOMP `SUBSCRIBE` 阶段校验订阅者的 `tenant_id` 和机器人访问权，防止手工订阅其他租户或未授权机器人的 Topic。

## 八、日志设计

### 8.1 操作审计日志

记录所有运营人员的操作行为，存入 PostgreSQL，保留 90 天。

```sql
CREATE TABLE audit_logs (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id   UUID NOT NULL REFERENCES tenants(id),
    operator_id UUID REFERENCES operators(id),  -- NULL 表示系统自动操作
    action      TEXT NOT NULL,       -- ROBOT_ACTIVATE / ORDER_CREATE / CREDENTIAL_REVOKE ...
    resource    TEXT NOT NULL,       -- 操作对象类型：robot / credential / operator ...
    resource_id TEXT NOT NULL,       -- 操作对象 ID
    detail      JSONB,               -- 操作前后的值、附加信息
    ip          INET,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
SELECT create_hypertable('audit_logs', 'created_at');
SELECT add_retention_policy('audit_logs', INTERVAL '90 days');
```

### 8.2 应用运行日志

记录服务运行状态、请求日志、错误堆栈等，接入**阿里云 SLS（日志服务）**。

优势：
- 全托管，无需维护日志文件和 logrotate
- 支持关键词搜索、SQL 分析、可视化图表
- 可直接配置告警规则（如错误率突增通知飞书）
- 与阿里云服务器原生集成，通过 Logtail Agent 采集，代码零侵入

日志保留 30 天，超出自动清理。

| | 操作审计日志 | 应用运行日志 |
|--|--|--|
| 存储位置 | PostgreSQL | 阿里云 SLS |
| 保留周期 | 90 天 | 30 天 |
| 用途 | 合规追责、操作审计 | 排查 bug、监控服务健康 |
